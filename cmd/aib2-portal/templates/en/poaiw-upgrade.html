二、升级类型判断

⚠️ 这是硬分叉 (Hard Fork)

原因：

  • 需要修改 BlockHeader 结构（添加推理 PoW 字段）
  • 需要修改区块验证逻辑（添加 PoW 检查）
  • 旧节点无法验证新区块

四、代码变更清单

1 BlockHeader 扩展 (pkg/utxo/block.go) 
type BlockHeader struct {
    Version       uint32
    PrevBlockHash [32]byte
    MerkleRoot    [32]byte
    Timestamp     uint64
    Height        uint64
    Proposer      [32]byte
    Signature     []byte

    // PoAIW 新增字段 (Version >= 2)
    InferencePoW  []byte  // 推理工作量证明
    ModelID       string  // 使用的模型ID
    EnergyClaim   uint64  // 声称消耗的能源
}
2 验证逻辑扩展 (pkg/utxo/validator.go) 
func (v *ChainBlockValidator) ValidateBlock(block *Block) error {
    // 现有验证...
    if err := v.validateExisting(block); err != nil {
        return err
    }

    // PoAIW 验证 (Version >= 2)
    if block.Header.Version >= 2 {
        return v.validatePoAIW(block)
    }
    return nil
}

func (v *ChainBlockValidator) validatePoAIW(block *Block) error {
    // 1. PoW 验证
    if !verifyInferencePoW(block) {
        return fmt.Errorf("inference PoW invalid")
    }
    // 2. 质押验证
    if !verifyMinStake(block) {
        return fmt.Errorf("insufficient stake")
    }
    return nil
}

五、升级路径选项

选项 时间 复杂度 风险 推荐度

B. 测试网先行 4-6周 中 低 ✅ 推荐
C. 双轨运行 6-8周 中高 中 ✅ 可行
D. 渐进迁移 8-12周 低 低 ✅ 最稳妥

六、推荐升级方案：测试网先行

阶段 1：准备 (Week 1-2)

  • 在测试网部署 PoAIW 代码
  • 运行集成测试
  • 更新文档和工具

阶段 2：测试网验证 (Week 3-4)

  • 测试网启用 PoAIW（Version 2 区块）
  • 监控网络稳定性
  • 收集节点反馈

阶段 3：主网提案 (Week 5-6)

  • 发布 AIP (AIB Improvement Proposal)
  • 社区讨论和投票
  • 设定激活高度

阶段 4：主网升级 (Week 7+)

  • 在指定高度激活 PoAIW
  • 观察链是否分裂
  • 紧急响应预案

七、关键决策点

⚠️ 需要社区决定的问题

  1. 激活时机：主网上线前还是后？
  2. 创世分配：PoAIW 如何影响现有质押？
  3. 参数调整：30% 质押 / 70% 推理比例是否合适？
  4. 向后兼容：是否保留 PoS 作为备用？

八、结论

当前测试网 可以 升级到简化版 PoAIW

但这需要硬分叉，建议采用测试网先行的渐进方案：

  • ✅ 代码已准备就绪（测试通过）
  • ✅ 架构支持版本化升级
  • ⚠️ 需要社区共识
  • ⚠️ 需要谨慎的激活策略
