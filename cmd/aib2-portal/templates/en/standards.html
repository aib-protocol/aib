Code Standards

Coding conventions, architecture rules, and collaboration requirements for the AIB 2.0 project.

Go Coding Conventions

Basic Rules

  • Go version: 1.22+, use latest stable standard library features
  • Prefer Go standard library, minimize external dependencies
  • Formatting: all code must pass gofmt
  • Static analysis: run go vet and staticcheck before committing
  • Naming: follow Go official naming conventions (Effective Go)

Error Handling

  • Return errors explicitly; no panic in library code
  • Wrap errors with fmt.Errorf("context: %w", err)
  • Custom error types implement the error interface
  • Error messages start with lowercase, no trailing punctuation

Testing Requirements

  • Test file naming: *_test.go
  • Use table-driven tests
  • Minimum test coverage: 85%
  • Include benchmarks for performance-critical paths

Architecture Rules

Project Structure

  • Follow Go standard project layout
  • Executables go in cmd/ directory
  • Core library code goes in core/ directory
  • Internal packages use internal/ for visibility restriction

Design Principles

  • Define interfaces in the consuming package, not the implementing one
  • Concurrency safety: protect shared state with sync package
  • Decouple modules through interfaces, avoid circular dependencies
  • Pass configuration via structs with sensible defaults

Collaboration Requirements

Commit Standards

  • Each commit focuses on a single change
  • Commit messages are concise and describe "why", not "what"
  • Changes must have corresponding tests

Inviolable Rules

  • Never modify the seven rules in GENESIS_RULES.md
  • Never introduce code that violates genesis rules
  • Never add premine or privileged address logic
  • Never grant AI nodes voting rights in governance decisions
