## 一、核心参数

### 1.1 总量与分配

| 参数 | 值 | 说明 |
|------|------|------|
| 总发行量 | 3,141,592,653 AIB | π × 10^8，与π同级 |
| 最小单位 | 1 satoshi = 0.00000001 AIB | 同比特币 |
| 创世区块奖励 | 50 AIB | 每个区块的基础奖励 |
| 初始节点数 | 假设100个 | 每个节点初始100 AIB |

### 1.2 区块奖励分配

```
区块奖励 = 50 AIB (Staking奖励 + 推理奖励)

分配方式：
├── Staking奖励: 30 AIB (60%)
│   └── 按质押权重比例分配
└── 推理奖励: 20 AIB (40%)
    └── 按推理贡献积分分配
```

### 1.3 时间参数

| 参数 | 值 | 说明 |
|------|------|------|
| 目标出块时间 | 10秒 | 平均10秒出一个块 |
| 成熟期 | 100区块 | Coinbase可花费需要100个确认 |
| 质押解锁期 | 7天 | 解除质押后7天可转账 |

## 二、PoS 质押机制

### 2.1 初始分配

```
假设100个初始节点：
节点001-100: 各100 AIB
总初始质押: 10,000 AIB
```

### 2.2 质押规则

```go
type StakeConfig struct {
    MinStake        uint64 = 10           // 最低质押 10 AIB
    MaxStake        uint64 = 1000000000   // 最高质押 10亿 AIB
    UnlockPeriod    uint64 = 7 * 8640     // 7天（假设10秒/块）
    SlashRatio      float64 = 0.5         // 作弊惩罚50%
}
```

### 2.3 出块者选择

```
公式：
出块概率 = 质押量 / 总质押量

示例：
节点A质押: 100 AIB → 1% 概率
节点B质押: 1000 AIB → 10% 概率
节点C质押: 10000 AIB → 100% 概率（每块）

注意：
- 每块重新抽签（不是轮询）
- 高质押不是"一定"出块
- 而是"大概率"出块
```

### 2.4 验证者状态根

```
每个区块头包含：
- ValidatorStateRoot: 所有验证者状态的Merkle根
- 任何人可以验证当前验证者集合
- 防止验证者状态被篡改
```

## 三、推理服务机制

### 3.1 分层推理接口

```
┌─────────────────────────────────────────────────────────┐
│                    推理接口分级                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Level 1: 基础接口                                     │
│  ├── 用途: 简单问答、文本生成                          │
│  ├── 质押要求: ≥ 10 AIB                               │
│  ├── QPS限制: 10次/秒                                 │
│  └── 评分权重: 1.0x                                   │
│                                                         │
│  Level 2: 高级接口                                    │
│  ├── 用途: 复杂推理、多轮对话                          │
│  ├── 质押要求: ≥ 1000 AIB                             │
│  ├── QPS限制: 100次/秒                                │
│  └── 评分权重: 2.0x                                   │
│                                                         │
│  Level 3: 专业接口                                    │
│  ├── 用途: 模型微调、大规模推理                        │
│  ├── 质押要求: ≥ 100000 AIB                           │
│  ├── QPS限制: 1000次/秒                               │
│  └── 评分权重: 5.0x                                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.2 推理结算（闪电网络模式）

```
流程：
┌─────────────────────────────────────────────────────────┐
│  用户                          节点                      │
├─────────────────────────────────────────────────────────┤
│                                                        │
│  1. 建立支付通道                                       │
│     用户预存 1000 AIB                                  │
│     节点预存 0 AIB                                    │
│                                                        │
│  2. 链下推理调用                                       │
│     用户请求推理 → 节点执行 → 返回结果                 │
│     每次更新通道余额                                   │
│                                                        │
│  3. 链上结算（需要时）                                 │
│     任意一方可以提交最终余额到链上                      │
│     另一方可以挑战（如果作弊）                         │
│                                                        │
└─────────────────────────────────────────────────────────┘

优势：
- 推理不需要等待区块确认（毫秒级响应）
- 高频调用不堵塞区块链
- 作弊代价：通道惩罚 + 声誉损失
```

### 3.3 推理定价

```
接口定价（示例）：
├── Level 1: 0.001 AIB/次
├── Level 2: 0.01 AIB/次
└── Level 3: 0.1 AIB/次

节点收益 = 调用次数 × 单价 × 评分权重
```

## 四、信任网络评分机制

### 4.1 评分系统

```
核心思想：
- 不验证"AI推理是否正确"（技术上困难）
- 用"信任网络"代替"技术验证"（经济激励）

每笔推理后：
用户对节点评分 → 分数与节点pubkey绑定
```

### 4.2 评分数据结构

```go
type ReputationScore struct {
    NodePubKey    [32]byte   // 节点的公钥
    Score         float64    // 分数 0.0 - 10.0
    Weight        float64    // 权重（基于评分者自身权重）
    Timestamp     uint64     // 时间戳
    Signer        [32]byte   // 评分者公钥
    Signature     []byte     // 评分者签名
}

// 评分内容
type ScoreContent struct {
    TargetPubKey  [32]byte   // 被评分节点
    Score         float64
    Reason        string      // "good_response", "bad_response", "timeout", "cheating"
}
```

### 4.3 评分验证（链上+链下）

```
链下（实时）：
┌─────────────────────────────────────────────────────────┐
│  用户提交评分 → 节点验证签名 → 更新本地评分            │
│                                                         │
│  if !VerifySignature(signature, scoreContent) {        │
│      reject("无效签名")                                │
│  }                                                     │
│  if scoreContent.TargetPubKey == myPubKey {            │
│      // 别人在给我打分                                  │
│      myScore = updateLocalScore(scoreContent)          │
│  } else {                                              │
│      // 我在给别人打分                                  │
│      signAndBroadcast(scoreContent)                    │
│  }                                                     │
└─────────────────────────────────────────────────────────┘

链上（周期性校验）：
┌─────────────────────────────────────────────────────────┐
│  每100个区块：                                          │
│  1. 收集所有节点的评分数据                              │
│  2. 验证签名有效性                                      │
│  3. 计算每个节点的最终权重                              │
│  4. 更新ValidatorStateRoot                             │
└─────────────────────────────────────────────────────────┘
```

### 4.4 权重计算

```
节点总权重 = 质押量 × 评分乘数

评分乘数计算：
乘数 = 1.0 + (平均评分 - 5.0) / 10.0

示例：
节点A: 质押1000, 评分9.0 → 乘数=1.4 → 有效权重=1400
节点B: 质押1000, 评分5.0 → 乘数=1.0 → 有效权重=1000
节点C: 质押1000, 评分2.0 → 乘数=0.7 → 有效权重=700

结论：
- 高评分 → 更高出块概率
- 低评分 → 降低出块概率
- 作弊 → 评分下降 → 收益下降
```

### 4.5 作弊检测与惩罚

```
作弊类型与惩罚：
┌─────────────────────────────────────────────────────────┐
│  作弊类型          │  检测方式      │  惩罚           │
├─────────────────────────────────────────────────────────┤
│  刷分              │  评分频率异常  │  权重降50%      │
│  抄袭结果          │  多节点结果一致│  权重降30%      │
│  拒绝打分          │  长期不评分    │  无法获得推荐   │
│  虚假推理          │  用户投诉     │  权重降80%      │
│  双花支付          │  通道挑战成功 │  罚没通道余额   │
└─────────────────────────────────────────────────────────┘
```

## 五、共识机制

### 5.1 出块流程

```
时间线：
T+0s:    区块高度 N-1 产生
T+0-10s: 节点准备区块 N
         ├── 收集待确认交易
         ├── 计算VRF确定出块者
         ├── 执行推理服务
         └── 更新评分数据
T+10s:   区块 N 广播
T+10-20s:其他节点验证
         ├── 验证交易签名
         ├── 验证出块者选择
         ├── 验证评分数据
         └── 接受或拒绝
```

### 5.2 区块数据结构

```go
type Block struct {
    Header: BlockHeader {
        Version:           uint32
        PrevBlockHash:     [32]byte
        MerkleRoot:        [32]byte
        Timestamp:         uint64
        Height:            uint64
        Proposer:          [32]byte           // 出块者
        Signature:         []byte             // 出块者签名
        VRFProof:          []byte             // VRF证明
        VRFSeed:           [32]byte           // 下轮随机种子
        ValidatorStateRoot:[32]byte           // 验证者状态根
    }
    Transactions:      []*Transaction
    ReputationUpdates: []ReputationScore     // 本区块收集的评分
}
```

### 5.3 交易类型

```
交易类型：
┌─────────────────────────────────────────────────────────┐
│  1. 普通转账                                          │
│     ├── 输入: UTXO引用                                │
│     ├── 输出: 目标地址+金额                            │
│     └── 签名: Ed25519                                │
│                                                         │
│  2. 质押交易                                          │
│     ├── 类型: STAKE_ADD / STAKE_REMOVE                │
│     ├── 金额: 质押量                                  │
│     └── 生效: 下个Epoch                               │
│                                                         │
│  3. 评分交易                                          │
│     ├── 类型: REPUTATION_UPDATE                       │
│     ├── 内容: 评分+签名                                │
│     └── 打包: 每100区块批量                           │
│                                                         │
│  4. 通道结算                                          │
│     ├── 类型: CHANNEL_SETTLE                         │
│     ├── 内容: 最终余额+签名                           │
│     └── 挑战期: 24小时                               │
│                                                         │
│  5. Coinbase                                          │
│     ├── 出块奖励: 50 AIB                              │
│     └── 分配: 30(质押) + 20(推理)                    │
└─────────────────────────────────────────────────────────┘
```

## 六、安全机制

### 6.1 双重验证

```
Layer 1: 数学验证（PoS）
├── 出块者选择：VRF证明
├── 交易签名：Ed25519
└── 状态根：Merkle树

Layer 2: 经济验证（信任网络）
├── 评分系统：声誉权重
├── 闪电网络：通道挑战
└── 作弊惩罚：经济损失
```

### 6.2 抗量子设计

```
当前保护：
├── Ed25519: 理论上可抗量子（待验证）
├── 评分历史: 无法篡改（链上）
└── 声誉系统: 不依赖加密（依赖经济）

未来升级：
└── 网络可投票升级加密算法
```

### 6.3 51%攻击防御

```
攻击成本：
- 需要控制51%质押
- 需要维持高评分（否则权重下降）
- 攻击成功收益 < 维护成本

防御机制：
├── 评分权重降低单点控制力
├── 闪电网络限制单次攻击收益
└── 长期攻击成本指数上升
```

## 七、经济模型

### 7.1 初始分配

```
创世分配：
节点001: 100 AIB
节点002: 100 AIB
...
节点100: 100 AIB
───────────────
总计:   10,000 AIB
```

### 7.2 发行计划

```
区块奖励: 50 AIB/块
年出块数: 3,153,600 (10秒/块)
年增发:   157,680,000 AIB

递减计划（每2年减半）：
Year 1-2:   50 AIB/块 → 157,680,000 AIB/年
Year 3-4:   25 AIB/块 →  78,840,000 AIB/年
Year 5-6:   12.5 AIB/块 →  39,420,000 AIB/年
...
停止: 达到31.4亿总量
```

### 7.3 收益来源

```
节点收益 = 出块奖励 + 推理服务费 + 推荐奖励

出块奖励：
└── 30 AIB(质押分配) + 20 AIB(推理分配)

推理服务费：
└── 用户支付（链下闪电网络）

推荐奖励：
├── 用户A推荐节点B
├── 用户A获得: 用户A使用推理费的5%
└── 节点B获得: 用户B使用推理费的2%
```
